中文： 大家好。今天我将向大家汇报我们的最新研究：基于 SMA-Beam 算法解决带时间窗的物流路径问题（TSPTW）。
首先讲一下行业痛点。在当前的电子商务时代，物流末端配送的成本在整个供应链中占比极高。车辆不仅要用最短的距离完成配送，还必须严格遵守每个客户指定的时间窗。如果早到，必须等待，这浪费了可用工时；如果迟到，不仅仅会导致任务失败，更会面临高额的赔偿金（Penalty Cost），严重蚕食企业的利润。
现有的研究中，精确算法（如 Branch and Bound）在问题规模变大时，计算时间呈指数级爆炸，无法满足工业界的实时响应需求。另一方面，传统的遗传算法（GA）或粒子群算法（PSO）在面对极强的时间约束时，很容易生成大量的不可行解（Infeasible solutions），使得大部分计算资源被浪费在无效的验证上。
这就是我们本研究的独创性所在。我们为什么偏偏选择了黏菌算法（SMA）？黏菌算法是一种基于黏菌管道网络扩张觅食行为的新型群智能算法。数学上，它没有复杂的突变逻辑，而是依靠一套天然的震荡反馈机制追踪极其复杂的空间梯度。这种特性非常适合处理高度非线性的时空耦合多维变量体系。

2. 详细解读数学模型与公式 (4-8分钟) / 数理モデルと数式の詳細な解説 (4-8分)
中文： 既然要把问题抽象给计算机，我们就必须看一看它的数学规划模型（MIP）。
首先是目标函数（Objective Function）。我们的目标不仅仅是跑的距离短，而是要最小化 Makespan，即车辆完成所有配送任务后返回车库的总耗时。这实际上是一个需要极度平衡“行驶距离”与“等待时间”的博弈。
其次是核心约束（Constraints）。最著名的是“时间窗约束”，公式表示为 `Arrival_Time(i) <= Due_Time(i)` 以及 `Start_Service(i) = max(Arrival_Time(i), Ready_Time(i))`。同时，还有车辆的容量约束等。
接下来是算法真正的心脏——SMA 的权重更新公式。在算法运行中，黏菌个体的位置代表了一条潜在的排班策略。系统会通过公式为每个个体分配动态权重矩阵 <span>$W$</span> 和探索概率 <span>$Z$</span>。
具体来说，<span>$W(i)$</span> 的计算依赖于个体的适应度与当前最优适应度之间的差异。对于得分排名靠前的前半部分个体，它们权重为正，就像发现了优质食物源的黏菌管道会快速变粗；对于后半部分个体，权重会降低甚至阻断。通过这个数学关系，黏菌的形态会自适应地朝可行域的核心区域收敛。而在迭代中引入的随机概率 <span>$Z$</span>，则保证了即便主体陷入局部最优，仍有一小部分菌丝在盲目搜索（Random Search）以防死锁。
日文： 課題をコンピュータに抽象化するために、ここで数理計画モデル（MIP）を見てみましょう。
まずは目的関数（Objective Function）です。私たちの目標は単に走行距離を短くすることではなく、Makespan、つまり車両がすべてのタスクを完了して車庫に戻るまでの「総所要時間」を最小化することです。これは実のところ、「走行距離」と「待機時間」のバランスを極限まで取るゲームなのです。
次にコアとなる制約条件（Constraints）です。最も有名な「時間枠制約」は数式で `Arrival_Time(i) <= Due_Time(i)` および `Start_Service(i) = max(Arrival_Time(i), Ready_Time(i))` と表されます。同時に、車両の容量制約なども存在します。
そして、アルゴリズムの本当の心臓部であるSMAの重み更新の数式について解説します。アルゴリズムの実行中、粘菌個体の位置は潜在的なスケジューリング戦略を表します。システムは計算式を用いて、各個体に動的な重み付け行列 <span>$W$</span> と探索確率 <span>$Z$</span> を割り当てます。
具体的には、<span>$W(i)$</span> の計算は、個体の適応度と現在の最適適応度との差に依存します。適応度のスコアが上位半分の個体に対しては、正の重みを与えられます。これは、良質な餌場を見つけた粘菌の管が急速に太くなるのと同じです。一方、下位半分の個体に対しては、重みが減少し、あるいは遮断されます。この数学的関係により、粘菌の形態は自適応的に実行可能領域のコアへと収束していきます。また、反復中に導入されるランダム確率 <span>$Z$</span> は、本体が局所解に陥ったとしても、一部の菌糸がデッドロックを防ぐために盲目探索（Random Search）を行うことを保証します。

3. 核心预处理与前向剪枝：四步收紧与三步剔除 (8-11分钟) / コア前処理と前方剪定：4ステップ引き締めと3ステップ除去 (8-11分)
中文： 前面提到了传统算法经常产生违法路线的痛点。我们是怎么用 Beam Search 解决这个问题的呢？除了搜索策略，更关键的是我们在底层引入了极度严格的规则过滤，最核心的便是**“四步时间窗收紧法则”**与**“三步网络剔除法则”**。
首先是“四步时间窗收紧”。在算法起跑前，我们会对所有客户的原始时间窗进行压缩：1) 依据车辆从起点出发的最早可能时间向后推导；2) 依据车辆必须返回车库的最晚时间向前推；3) 利用前序节点的最短到达时间收敛当前下限；4) 利用后序节点的最晚离开极限压缩当前上限。这四步操作将每个客户原本宽泛的时间边界极限压缩，把冗余的等待时间提前从数学模型中狠狠抠除。
其次是“三步网络剔除法则”。它用于在搜索时直接断开不可能的路径边缘：1) 节点间不相容剔除（如果从 A 直接去 B 哪怕全速行驶也会导致 B 迟到，直接断开 A-B 边）；2) 时间窗互斥剔除（两节点的开放时间存在硬冲突，完全无法兼容，切断相连可能性）；3) 归回车库防守剔除（若走某条边后，无论如何都赶不及在下班前驶回总库，则剔除这步作死的走法）。
我们在运用 Beam Search 时正是依赖这些法则：假设当前面临 A、B、C 三个候选。由于 B 的时间窗很紧，普通算法可能会盲目先去 A 再去 B。但我们的算法在检测 A-B 边时，会瞬间触发“节点不相容剔除”，因为推算显示再去 B 铁定超时。这一“死胡同分支”在进行树搜索扩展的第一步就被瞬间剪枝丢弃！依靠这些多维度的剪枝法则，我们绝对保证了解码输出的路线不仅合法，而且高度精简。
日文： 先ほど、従来のアルゴリズムが頻繁に違反経路を生成するというペインポイントについて触れました。私たちはこれを Beam Search（ビームサーチ）を用いてどのように解決したのでしょうか。探索戦略だけでなく、さらに重要なのは、基層に極めて厳格なルールフィルタリングを導入していることです。その中核となるのが**「4ステップ時間枠引き締め規則（4-Step Time Window Tightening）」**と**「3ステップネットワーク除去規則（3-Step Network Elimination）」**です。
第一に、「4ステップ時間枠引き締め規則」です。アルゴリズムの実行前に、すべての顧客の元の時間枠を圧縮します。1) 車両が起点から出発する最短可能時間から後方へ推論し、2) 車庫へ帰還しなければならない最遅時間から前方へ逆算します。3) 先行ノードの最短到着時間を利用して現在の下限を収束させ、4) 後続ノードの最遅出発限界を利用して現在の上限を圧縮します。この4ステップの操作により、各顧客の本来広かった時間境界を極限まで圧縮し、冗長な待機時間を数理モデルから徹底的に排除します。
第二に、「3ステップネットワーク除去規則」です。これは探索時に不可能な経路エッジを直接切断するために用いられます。1) ノード間の非互換性による除去（AからBへ全速力で向かってもBで遅刻する場合、A-Bエッジを直接切断）、2) 時間枠の相互排他による除去（2つのノードの開放時間にハードコンフリクトがあり全く両立しない場合、接続の可能性を遮断）、3) 車庫防衛のための除去（あるエッジを通るとどうやっても終業前に本社に戻れない場合、その致命的な進行を削除）を行います。
ビームサーチを適用する際、まさにこれらの規則に基づいています。例えば、現在A、B、Cという3つの候補に直面しているとします。Bの時間枠が厳しいため、通常のアルゴリズムは盲目的に先にAに行き、その後Bに行こうとするかもしれません。しかし我々のアルゴリズムは、A-Bエッジを検出した瞬間、Bでの遅刻が確定している計算になるため「ノード非互換性による除去」が即座にトリガーされます。この「行き止まりの枝」は、木探索拡張の第一歩で即座に剪定（切り捨て）されます！これらの多角的な剪定規則に依存することで、デコードして出力されるルートが合法的であるだけでなく、高度に洗練されていることを完全に保証しています。
